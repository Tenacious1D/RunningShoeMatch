## A structured starting point

Running Shoe Match is being built around structured shoe records rather than product claims copied from one page to another. A shoe profile can hold its current specifications, available metrics, ranking placements, and retailer options in one place.

That separation matters for editorial content. A guide can focus on explaining *how to compare* shoes, while the embedded profile below asks the database for the latest public record each time the site refreshes its cached data.

## What stays current

The MDX file contains only the stable shoe slug. It does not contain a price, affiliate URL, score, or copied specification. If an editor updates the shoe record or retailer links later, every article using the component can reflect that change without rewriting old prose.

This pattern is intended for details that naturally change:

- active retailer destinations and displayed prices
- current public shoe specifications
- a shoe's current publication status
- the newest published ranking snapshot

Historical statements should still be written as dated editorial facts. A sentence about what ranked first in a specific month should not silently change with the live component.
